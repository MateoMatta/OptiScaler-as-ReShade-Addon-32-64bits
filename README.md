## About

**OptiScaler** is a tool that lets you replace upscalers in games that ***already support DLSS2+ / FSR2+ / XeSS*** ($`^1`$), as well as manage ***frame generation*** in already mentioned games _(either by replacing existing FG options or enabling it in DX12 games through experimental ***OptiFG***)_. It also offers extensive customization options for all users, including those with Nvidia GPUs using DLSS.

> [!CAUTION]
> * We've been informed about some **FAKE websites** presenting themselves as OptiScaler team, so we would like to strongly highlight that we **DO NOT HAVE an official website!**  
> * We **DON'T have an official manager app**, so please be careful when downloading or using them! And please don't bother us to provide support for something which isn't even ours!
> * Only **LEGIT places** are this Github, our Discord server and Nitec's NexusMods page.  
> * OptiScaler is **FREE**, any kind of monetary requirements are scams!  

> [!TIP]
> _For example, if a game has DLSS only, OptiScaler can be used to replace DLSS with XeSS or FSR 3.1 (also works for FSR2-only games, like The Outer Worlds Spacer's Choice, albeit requires manually providing nvngx_dlss.dll)._

**Key aspects of OptiScaler:**
- Enables usage of XeSS, FSR2, FSR3, **FSR4**$`^2`$ (_officially, RDNA4 and RDNA3 dGPUs only_) and DLSS in (temporal) upscaler-enabled games
- Allows users to fine-tune their upscaling experience with a wide range of tweaks and enhancements (RCAS & MAS, Output Scaling, DLSS Presets, Ratio & DRS Overrides etc.)
- Since v0.7.0+, added ***experimental DX12*** frame generation support with possible HUDfix solution ([**OptiFG**](#optifg--hudfix-experimental-hud-ghosting-fix))
- Supports [**Fakenvapi**](#installation) integration - enables Reflex hooking and injecting _Anti-Lag 2_ (RDNA1+ only), _LatencyFlex_ (LFX) or _XeLL_ - _bundled since 0.9_  
- Since v0.7.7, added support for **Nukem's** FSR3-FG mod [**dlssg-to-fsr3**](#installation), only supports games with ***native DLSS-FG*** - _bundled since 0.9_
- Since v0.7.8, added **ASI plugin loading** support (_disabled_ by default (`LoadAsiPlugins=` in INI), loads from customisable folder, default `plugins`)
- New project - [**OptiPatcher**](https://github.com/optiscaler/OptiPatcher) - an ASI Plugin for OptiScaler for enabling DLSS and DLSSG inputs without spoofing in ***supported games***.
- Since v0.7.8, OptiScaler is now automatically applying certain game patches for a better out-of-the-box experience
- Since v0.9.0, separated FG Inputs and Outputs, added XeFG and FSR4-FG support, as well as bundled Fakenvapi and Nukem's FSR3-FG mod
- For a detailed list of all features, check [Features](Features.md)

## How it works?
* OptiScaler acts as a middleware, it intercepts upscaler calls from the game (_**Inputs**_) and redirects them to the chosen upscaling backend (_**Output**_), allowing user to replace one technology with another one. **Inputs -> OptiScaler -> Outputs**  
* _Or put more bluntly, **Input** is the upscaler used in game settings, and **Output** the one selected in Opti Overlay._
* _Same goes for FG options which are separated into **FG Input** and **FG Output**._

### Experimental ReShade add-on build

The experimental x64 target emits `OptiScaler.addon64` and registers with ReShade. This is a **DX11 diagnostic probe only**: it logs adapter LUID and ReShade swapchain metadata, the native DXGI swapchain description and `GetBuffer` result for each native buffer, and a sampled current back buffer at ReShade's `present` callback (before API presentation). A nonzero buffer returning `DXGI_ERROR_INVALID_CALL` is recorded as inaccessible, not as evidence of a game error; other failures remain explicit errors. At Debug level it also logs observed DX11 texture creation, resource/view destruction, texture view creation, and sampled render-target/depth bindings (the first 30 and every 300th binding). ReShade resource events may repeat and only cover events observed after registration; they are not an enumeration of every live resource. Handles are diagnostic identifiers, valid only during callbacks and potentially reused. A depth-stencil usage or texture format identifies a candidate, not valid depth or motion vectors. The probe reads metadata only: it does not copy pixels, validate contents, submit frames to upscalers, or alter the frame. Other APIs are identified but their resources are outside this stage.

For the first 30 and every 3000th DX11 binding, `bound_view` events resolve non-null color and depth views to their underlying resources during that callback and record both formats, dimensions, sample count, usage and view subresources. Join them to `bind_targets` by `sequence`; each includes the `device` and `command_list` identifying the observed context. The process-wide `present_counter` is only a rough ordering hint: multiple swapchains, deferred command lists and concurrent callbacks prevent it from proving that a binding belongs to a particular presented frame. Missing or dropped events, ReShade's sampling, creation before registration and handle reuse limit correlation. No candidate is automatically selected or identified as an upscaler input.

`bound_view_sample probe_us` measures CPU wall time for a detailed binding callback, including metadata lookups and log formatting/enqueueing, but not asynchronous log output or GPU time. It does not measure overhead on unsampled callbacks or total frame time.

The add-on reads `[Log]` from `OptiScaler.ini` beside the add-on. `LogToFile` defaults to true for this probe, `LogLevel=1` enables resource Debug events (`0` includes Debug), `LogToDebug` enables debugger output, and `LogToConsole` writes Info and higher to an existing standard output. It does not allocate a console. `SingleFile=false` uses a process ID and performance-counter suffix for each add-on load; collect all matching files from a run. `LogFileName=auto` uses `OptiScaler-ReShade.log` beside the add-on. A custom `LogFileName` uses its directory and stem with `-ReShade.log` appended, keeping it distinct from the proxy log; relative names are relative to the add-on directory. A dedicated worker writes batches from a bounded 4096-entry queue. Producers wait for its lock and, if the queue fills, for space rather than dropping events on contention or overflow. A slow or blocked sink can therefore stall rendering or shutdown; this mode prioritizes diagnostic completeness over frame pacing. Normal unload drains the queue and appends `event=logger_shutdown` with drop, write failure, queue wait, high-water and formatting/truncation counters. Failed writes, forced termination or callbacks racing with shutdown can still lose events; a clean summary is not a durability guarantee against a crash or power loss. Diagnostic logging still has overhead and is not a benchmark. The worker always uses one thread regardless of the proxy's `LogAsync` and `LogAsyncThreads` settings. The add-on does not support `LogToNGX`, `OpenConsole`, or `CreateDumps`; these are proxy facilities. Add-on events cannot replicate NGX or backend logs without actually running those paths.

Every 300 observed presents, `logger_progress` reports cumulative dropped Debug and Info/error events, queue waits, queue high-water mark and truncated messages so losses and backpressure are visible even if normal unload is not recorded. Counters are independently read and may temporarily differ from their sum while callbacks run. These statistics may be absent on forced termination or write failure.

`tests/addon_logger_stress.cpp` supplies a minimal mock ReShade host for the built add-on. Run it against a copy in an isolated directory with `LogToFile=true`, `LogLevel=0`, `SingleFile=true` and an absent `OptiScaler-ReShade.log`; it invokes 160,000 concurrent null-swapchain present callbacks. Check the log contains exactly 160,000 `event=present error=null_swapchain` lines and that the shutdown counters report zero drops, write failures and truncations. The optional `--pause-worker` argument suspends only the mock process's identified worker briefly to force the queue to fill; additionally verify `queue_high_water=4096` and `queue_waits>0`. Do not use this artificial suspension in a game or production process.

The add-on entry point is ReShade's add-on registration and callback API. `Source.def` continues to describe OptiScaler's proxy exports; those names are not an `NVSDK_NGX_*` add-on ABI, and this diagnostic does not call an NGX entry point. The `.addon64` target is not a functional replacement for the normal proxy DLL.

The proxy front end is built separately with `MSBuild OptiScaler.sln /p:Configuration=Release /p:Platform=x64 /p:OptiScalerFrontend=Proxy`; this selects the proxy `DllMain`, emits a `.dll`, and uses a separate intermediate directory. The default `Release|x64` build remains the ReShade `.addon64`.

When the proxy is active (not in pass-through mode), it writes its own `OptiScaler.log` beside the proxy DLL by default when `[Log] LogToFile=auto`; setting `LogToFile=false` explicitly disables it. The default log level is Trace (`LogLevel=0`). A configured `LogFileName` is respected. This is separate from the add-on's `OptiScaler-ReShade.log`.

The recommended end state is to keep both artifacts, but build them from separate frontends over a shared OptiScaler core: the existing proxy `.dll` keeps its proxy exports and startup path, while `.addon64` registers with ReShade and adapts ReShade resources and synchronization to the core. They must not be produced by copying or renaming the same binary. A 32-bit game would still need an x86 capture add-on and an x64 host; see the carrier design notes in [DLSS5-Reshade-AIO](../DLSS5-Reshade-AIO/README.md). Color alone is insufficient for most temporal upscalers; depth, motion vectors, jitter, exposure, reset state, and correct GPU synchronization must be supplied or explicitly handled as unavailable.

## Which APIs and Upscalers are Supported?
Currently **OptiScaler** can be used with DirectX 11, DirectX 12 and Vulkan, but each API has different sets of supported upscalers.  
[**OptiFG**](#optifg--hudfix-experimental-hud-ghosting-fix) currently **only supports DX12** and is explained in a separate paragraph.

#### For DirectX 12
- XeSS (Default)
- FSR 2.1.2, 2.2.1
- FSR 3.X (and FSR 2.3.X)
- FSR 4.X (via FSR 3.X/4, _officially RDNA4 and RDNA3 dGPUs only_)
- DLSS

#### For DirectX 11
- FSR 2.2.1 (Default, native DX11)
- FSR 3.1.2 (unofficial port to native DX11)
- DLSS (native DX11)
- XeSS 2.X (native DX11, _Intel ARC only_)
- XeSS, FSR 2.1.2, 2.2.1, FSR 3.X w/Dx12 (_via D3D11on12_)$`^1`$
- FSR 4.X (via FSR 3.X/4 w/Dx12 interop, _officially RDNA4 and RDNA3 dGPUs only_)

> [!NOTE]
> <details>
>  <summary><b>Expand for [1]</b></summary>
>
> _**[1]** These implementations use a background DirectX12 device to be able to use DX12-only upscalers. There's a performance penalty up to 10-ish % for this method, but allows many more upscaler options. Also native DX11 implementation of FSR 2.2.1 is a backport from Unity renderer and has its own problems of which some were fixed by OptiScaler._
> </details>

#### For Vulkan
- FSR 4.X (via FSR 3.X/4 w/Dx12 interop, _officially RDNA4 and RDNA3 dGPUs only_)
- FSR2 2.1.2 (Default), 2.2.1
- FSR3 3.1 (and FSR2 2.3.2)
- DLSS
- XeSS 2.x

#### OptiFG + HUDfix (experimental HUD ghosting fix) 
**OptiFG** was added with **v0.7** and is **only supported in DX12**. 
It's an **experimental** way of adding FG to games without native Frame Generation, or can also be used as a last case scenario if the native FG is not working properly.  
* Currently supports FSR3-FG (requires HUDfix to avoid HUD ghosting), XeFG and FSR4-FG (ML model deals with the HUD, so may or may not require HUDfix).

For more information on OptiFG and how to use it, please check the Wiki page - [OptiFG](https://github.com/optiscaler/OptiScaler/wiki/OptiFG).
